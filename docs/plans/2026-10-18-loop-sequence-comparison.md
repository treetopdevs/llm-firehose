# Loop Observatory: compare captured sequences

Base: latest origin/main e007b2f (PR36). Fresh worktree codex/loop-sequence-comparison. Existing unmerged prototypes remain separate. User delegated routine design and test-seam decisions.

## Outcome

Extend the existing Loop Observatory beyond category totals: choose two consecutive-occurrence intervals of the same Error Signature, see which recorded activity runs match or differ, and inspect the captured observations behind each run. This advances the brainstorm's read/edit/test/fail comparison without inventing a strategy classifier from reduced payloads.

## Contract

- Use the existing scoped, sorted, deduplicated Loop model. An interval excludes its first recurrence and includes the next. Existing timestamp ordering and fallback membership disclosures remain visible; no new chronology or causal claim.
- Tokens are exact structured source, category, event.name, recorded severity and optional payload.tool_name. Use collision-free JSON tuples; canonicalize object-valued tool metadata by sorted keys. Distinguish absent, string and opaque/redacted values. Only string tool names are readable labels; missing/opaque values are explicitly unavailable and never inferred. Adjacent equal tokens become one run with exact count and ordered event references. Do not classify reads, edits, tests, successful work, attempts or strategies from names or absent payloads. Different token field or count means a different run. The closing recurrence remains explicitly marked on the run containing it, even if preceding observations have the same severity/token. Labels say these are reduced timeline fields; equal runs do not establish equal commands or strategy.
- Compare one selected interval against another numbered interval from the SAME active signature. A is the currently selected interval. Choose B with a bounded numeric input (1-based existing interval numbering) and an explicit Compare sequences button; default to preceding interval, or next for interval1, but never auto-run comparison. Reject self-comparison and noninteger/out-of-range values. Preserve the existing evidence list and Next evidence behavior. Selection resets on source/session/signature change and load/refresh. One resetComparison helper owns comparison state and cancels Loops-local detail. Store A/B identity as endpoint ID pairs, never only indexes. On late membership rederive, retain both only if both endpoint pairs survive in the same active signature, update their numbering and rebuild once; otherwise clear comparison entirely and announce why. With only one interval show why comparison needs a third occurrence.
- Deterministic longest-common-subsequence alignment of complete runs when both have at most200 runs; each matrix at most201x201. Row types are match / only-A / only-B. Prefer a diagonal exact token+count match, then consume A before B on equal remaining LCS lengths. Pin an ambiguous A/B sequence test. At most400 rows, ten40-row pages. Different counts produce explicit only-A/only-B rows with counts visible; no implied absence of the underlying tool. Equality is exact for all runs, including counts; no percentage score, fuzzy matching or outcome inference.
- If either exceeds200 runs, disclose alignment unavailable; show both complete sequences via pagination without prefix-based equality claims. Total sequence memory scales with the two selected intervals, not all interval pairs. No automatic pairwise comparison or session fanout. Derive runs/alignment only when a pair is explicitly selected or retained pair inputs change after late membership; cache the rendered comparison state across ordinary draw/page actions. A100k alternating-event test must take the unaligned O(n) path without a matrix.
- Render at most40 aligned rows or40 runs per side at once. Each run permits opening an accessible paginated list of its observations (40/page), and explicit receipt lookup uses the existing cancellation/identity guards. Comparand edits, comparison execution, run open/close and every comparison pager cancel pending/current Loops-local detail; never touch the shared detail pane. Keep existing selectEvent identity/version/abort checks. Never fetch details merely to compute a comparison. Captured labels use textContent and stripControl, displaying at most160 characters with explicit truncation disclosure; full stored evidence is available via explicit inspection. Use a semantic table with scoped column headers and textual match/only-A/only-B statuses; paged fallback uses labelled lists. Namespace all data-keys by comparison region, side and run/row index. Distinct Next A runs / Next B runs / Next comparison rows / Next run observations labels avoid ambiguity. Stable status announces ranges; after redraw restore focus to an enabled matching control or the region heading.
- Label matching as same recorded source/category/name/count only. Differences may reflect capture gaps, duplicate start/end observations or tool-name changes. Repeated strategy, retry, content changes and success remain unknown. All-source scope retains source identity in every token.
- Real unmodified fixtures have only one interval per qualifying signature, so browser/DOM comparison scenarios must explicitly label normalized contract mutations of those fixtures. No new API, dependency, persistence, capture behavior or frozen contract change.
