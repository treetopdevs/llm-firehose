Agent Firehose · design review · July 2026

From Firehose to Interrupt System

Product design & HCI/UX analysis of the 13-feature post-v0.1 roadmap · adversarial reviews from three independent models (Claude, Codex, Antigravity/Gemini) · revised Phase 1 & 2 plans. Written against the actual repo state on feat/daemon-desktop-migration.

0 · TL;DR

All three reviewers and the lead analysis converged on the same reframe: the roadmap is written for watching agents, but the durable value of this product is letting the user safely stop watching. The headline feature is not the feed — it's the interrupt system: "session 3 is blocked on a permission prompt; sessions 1 and 2 are about to collide on schema.sql." Judge every feature by whether it improves the precision of that one interrupt.

But — explicit design goal from the author: the detail-rich raw firehose (timeline / flow, watchable like good logs) is a first-class, permanent surface. It is the soul of the tool and the reason it exists; it's just not the headline. This resolves the biggest UX dispute cleanly: raw feed stays the default view, threads become a toggle, and craft investment in the feed (density, flow, color discipline, pause-on-scroll) is legitimate product work, not indulgence.

Sequencing correction all reviewers demanded: capture-quality honesty metadata moves from last-in-Phase-1 to first — every derived feature (threads, detectors, autopsy, weather) must degrade honestly on partial capture, and capture fidelity varies wildly by adapter (rich Claude Code hooks → blind procwatch).

Cut or parked by consensus: Arena, Capsules-as-handoff, Watchtower enforce mode, the .afrec repo-state reconstruction, the custom query language, the standalone menu-bar app. Each has a written revival trigger in §8.

Codex's forensic pass added a Phase 0 nobody else saw: the spool — contractually "the canonical source of truth" — currently excludes Codex and procwatch events entirely (broadcast-only, never persisted), and the codex adapter discards the native call_id that Threads would need. Before any derived feature, capture integrity itself must be repaired: spool everything, preserve native IDs, mark gaps. Its reframe sharpens the whole thesis: the trust boundary is epistemic — the product that always tells you what was observed, what wasn't observable, and which conclusions the evidence justifies, with unknown as a first-class result.

1 · Design goals & framing

1.1 Stated goals

  • The firehose itself is a goal, not a means. The author likes watching logs. A detail-rich, aesthetically excellent live timeline/flow view is intrinsic to the product identity — comparable to how htop or a good tmux dashboard is partly a pleasure object. Keep and polish it forever.
  • Local-first, free OSS, macOS-first, 1–2 maintainers at side-project pace.
  • Never break the agent; capture fails silently; five frozen contract surfaces.

1.2 The supervisory-control lens

Agent Firehose is an attention product. A developer running 2–4 agents is in a classic supervisory-control loop, and the roadmap's four questions map onto Endsley's situation-awareness levels: perception (what's happening) → comprehension (what does it mean) → projection (is it progressing) → control (should I intervene). The plan's blind spot: it organizes by features, not by the user's attention states:

ModeUser stateNeedsSurface
PeripheralWorking on something else; agents in backgroundCalm, glanceable "fine / needs me / broken"Notification, tray/status line
TriagePinged; 10-second decisionThe reason + evidence, one screen, zero navigationAttention list → feed
ForensicSomething went wrong; will spend 5–20 minReplay, provenance, autopsySession drill-down
Ambient watchingThe author's stated pleasure mode: feed on a second monitorFlow, density, beauty, pause-on-scrollThe raw firehose

The original Phase 1 served forensic + ambient modes; daily retention comes from peripheral + triage. Revised Phase 1 (§6) serves all four, with ambient-watching craft explicitly budgeted rather than smuggled in.

1.3 The wedge

The one thing agents' own UIs structurally cannot do: cross-agent, cross-session awareness on one machine. Claude Code shows its own session beautifully; nothing shows four sessions from three vendors, ranked by who needs you, with collision warnings. Notably, the repo has already started voting for this — internal/index/attention.go exists on the current branch before this review was written.

2 · The 13 features, adjudicated

Verdicts synthesize the lead analysis and all three adversarial reviews. KEEP = build as scoped · RESHAPE = build a materially different version · PARK = written trigger in §8 · CUT = drop from roadmap.

1 · Threads RESHAPE

Right instinct, wrong default and wrong ambition. Ship turn-scoped grouping only — group strictly by native session/turn/tool_call IDs (zero inference), call them "turns," as an opt-in toggle (t) over the raw feed. No semantic phases; outcome labels limited to facts (active/ended). "Abandoned" is unknowable — it's also what "user went to lunch" looks like. Grouping quality varies by adapter (rich for Claude Code hooks, guesswork for Codex tailing, impossible for procwatch), so threads must display per-session capture fidelity. A mis-grouped thread on day one poisons trust in every later derived feature; derived views must earn default status.

2 · Flight Recorder RESHAPE

Visual replay yes; repo-state reconstruction no. The deep version is a correctness tarpit: Firehose doesn't observe every mutation (user edits, formatters, unhooked subshells, out-of-band git), and balanced-privacy mode truncates payloads to 240 runes — a truncated diff is an unappliable diff. First divergence → hash mismatch → lie or "reconstruction failed" for most real sessions. Honest v1: event-scoped replay — step/scrub through a session's events showing each event's own captured output/diff, with an explicit "repo state is not reconstructed" disclaimer. Cut the .afrec portable format (a sixth frozen surface the contract would carry forever); the Capsule bundle (§2.9) covers portability.

3 · Why View / provenance graph RESHAPE

No graph UI — a graph in a character grid is unreadable past ~10 nodes, and even in the GUI it's Langfuse-shaped work. The edge taxonomy overreaches: failed-because and resolved are semantic claims that temporal adjacency cannot earn — "fabrication with a confidence score stapled on." Honest v1: "why" cards — press w on any event, get an indented linear chain built only from native-ID edges (same tool_call_id, same turn, same file). The provenance data model (relationship fields) goes in the foundation; the graph visualization may never need to exist.

4 · Workspace Radar RESHAPE

The collision kernel is the single most differentiated idea in the list; the full radar surface is not. Two reviewers noted most local agent use is still serial, and IDEs already show changed files. Ship collision + ownership signals as derived events in the main feed ("⚠ codex-2 and claude-1 both edited src/auth/token.go in the last 4m") — same data, no new surface, immediate value. The tree-view radar becomes a desktop-shell feature later, if multi-agent usage data justifies it.

5 · Progress Intelligence PARK (mostly)

Good detector list, catastrophic alert-fatigue math. "Same command failing repeatedly" fires on normal TDD — the workflow this repo mandates; "tests re-run on unchanged repo" fires on flake-hunting. Even 95% per-firing precision yields several false alarms/hour across 3 agents, and users hard-ignore a WARN channel after ~3 false alarms. Phase 1 ships only the 2–3 near-zero-FP detectors as attention events (blocked-on-permission, erroring, silent-too-long); the full detector framework waits for post-Autopsy demand, ships off-by-default, with per-detector precision fixtures, coalescing per session, and one-key "this was wrong" feedback.

6 · Arena CUT

Unanimous cut. Methodologically bankrupt across heterogeneous adapters: Claude Code hooks vs. Codex transcript-tailing are different measurement instruments, so every comparison is confounded by capture fidelity before model nondeterminism even enters. Presumes a rare workflow (deliberately racing agents), needs task-identity ceremony, and serves agent researchers, not engineers shipping code. If demand ever materializes, firehose compare sess_a sess_b is a weekend table on top of Autopsy metrics — it never needs to be a "lab."

7 · Session Autopsy KEEP

High value, deterministic-first is the whole feature. Two additions: the report leads with capture fidelity ("covers ~83% of observable actions; responses redacted") — an autopsy that overclaims is worse than none — and v1 drops the pluggable summarizer entirely (no model dependency). Markdown/JSON export. Bonus: the autopsy is the naturally shareable artifact that markets the tool.

8 · Watchtower ENFORCE: CUT OBSERVE: PARK

Enforce mode contradicts the project's own prime directive ("never break the agent; fail silently") and is unenforceable by architecture on the codex adapter (post-hoc tailing — Firehose learns of actions after they happen; TOCTOU everywhere else). Partial enforcement users believe is total is negative safety, plus unbounded liability for a free tool. Enforcement belongs upstream in the agents' own permission systems. Observe-mode collapses into derived warn events (i.e., Lenses/detector rules with a warn action) — parked with them. See §8 for the gateway-architecture trigger.

9 · Capsules RESHAPE

Cross-agent handoff is a losing race against vendors (native resume/session-sharing are vendor roadmap items), and a continuation prompt generated from redacted, truncated payloads will be lossy garbage exactly when it matters. The durable core is the neutral evidence bundle: extend /export to a directory bundle — autopsy.md + events.ndjson + patches/ + manifest.sha256 + privacy manifest. Let the ecosystem write converters. No continuation-prompt generator.

10 · Lenses / query language RESHAPE

All reviewers rejected the custom grammar — a parser, grammar doc, error messages, completion, and a forever-compat surface for an audience fully served by hotkeys. Evidence from the field: lnav, k9s, htop thrive on hotkeys + / fuzzy filter; tools with real query languages have docs teams and query builders. The claim "Lenses are the substrate" conflates the internal predicate engine (yes — build it; detectors need it) with the user-facing language (defer; revisit only as familiar key:value pairs, never an invented grammar). Ship: 5–7 hotkey lenses (errors-only, current-repo, shell-only, active-sessions, warnings) + substring filter + a named-views TOML.

11 · Control Room RESHAPE

The plan buried the cheap half under the expensive half. The glanceable half — active-sessions list ranked by needs-attention, with conflicts — is Phase-1-worthy and is exactly what attention.go starts. The actions half (pause/terminate/approve) stays last, and per the Watchtower verdict may live upstream forever; tmux and Activity Monitor already cover kill.

12 · Repository Weather RESHAPE

Keep the concept as a status line in the TUI header and desktop shell (state + expandable evidence); cut the standalone menu-bar companion app (a second release pipeline for a status gimmick — though the Tauri tray icon gets the count for free). Weather states are derived data and obey the same honesty rules: every state expandable to evidence, degraded gracefully under partial capture.

13 · Adapter Lab RESHAPE

Right idea, wrong packaging: not a UI — a CLI + golden-fixture contract (firehose adapter dev --replay fixtures/, coverage report, redaction preview). Contributors live in the terminal and CI; a workbench UI serves ~5 people. This is also self-defense: adapter rot against quarterly upstream format changes is the roadmap's true competitor, so anything that cheapens adapter maintenance pays rent forever.

2.1 The hidden foundation — confirmed, reordered

All reviewers endorsed the foundation section and demanded it move ahead of the features: capture-quality metadata first (it's the honesty layer everything degrades against), then relationship fields (tool_call_id, parent_event_id, thread_id — all schema-additive, so no version bump), then the derived-data store (separate NDJSON, never rewriting the spool), then the artifact registry. One contract warning surfaced: the moment the desktop app renders a derived structure over the daemon API, its semantics become a de facto frozen surface — the plan treats derived data as freely revisable while also making it UI-load-bearing. Resolution: derived data is exposed under an explicitly versioned, explicitly unstable API namespace (/derived/*, marked experimental in contracts.md) until it earns stability.

3 · HCI/UX deep dive

3.1 Trust architecture: observed vs. derived

The single most important UI convention in the entire product: every inferred row carries one consistent visual mark (e.g., ≈ prefix + dimmed style) — thread outcomes, detector warnings, why-chains, weather states. Users generalize a single visible inference error to all derived data (automation-bias literature is symmetric: one bad output causes disuse). One glyph, applied everywhere, carries the whole trust story. Corollary: evidence-expansion UX ("every conclusion expandable") is 3–5× the cost of computing conclusions — budget it per feature or the transparency promise is marketing.

3.2 The feed as craft object

Since ambient watching is a stated goal, the feed deserves deliberate design, not defaults:

  • Pause-on-scroll is mandatory (like less +F): reading in a moving feed is the #1 firehose UX failure. space pauses; new-event count accumulates in the header; G resumes tail.
  • Color discipline: severity gets color; recency gets position; each session gets a stable glyph/color pair; everything else monochrome. If >~10% of rows are colored, the pre-attentive channel is dead.
  • Density ladder (progressive disclosure): feed row (1 line) → expanded event (inline, n lines) → session view (full screen) → artifact/diff (pager). One keypress in (enter), one out (esc), no modal stacks.
  • Burst aesthetics: the existing ×N coalescing is the right primitive — extend it into turn grouping rather than replacing it.
  • Flow rendering: a subtle per-session left-gutter thread line (│ ├ └) gives the "flow" feel without a graph engine.
14:03:12 CLAUDE·a91 api │ ✓ go test ./internal/auth 1.2s 14:03:14 CLAUDE·a91 api ├ edit middleware.go +18 −4 14:03:19 CODEX·c13 api │ read token.go 14:03:21 CODEX·c13 api ├ ✗ npm run lint ×3 14:03:30 ≈ derived ⚠ collision a91 + c13 both writing src/auth/ (evidence: 4 events) 14:03:41 ≈ derived ● attention c13 blocked on permission prompt 2m 10s

Sketch: stable session colors, one derived-row glyph (≈), gutter flow lines, coalesced bursts (×3), monochrome bulk.

3.3 Keyboard contract & discoverability

A TUI keymap budget is ~20 mnemonics before discoverability collapses. Reserve now: / filter · 1–7 lenses · t turn-grouping toggle · enter/esc zoom ladder · w why · a autopsy · space pause · g/G top/tail · ? help. When the map approaches budget, the answer is a command palette (⌘K-equivalent, e.g. :) — which is itself a feature to schedule, not an afterthought.

3.5 The two-surface question (TUI vs. Tauri)

Two reviewers flagged split-personality risk: chasing parity ships two mediocre interfaces. Decision rule adopted: the TUI is the canonical, complete surface for feed + attention + autopsy; visually-heavy forensics (replay scrubber, any future radar/graph) are desktop-only — and each desktop-only feature must justify the daemon-API surface it adds. Never build an ASCII approximation of a feature that is naturally graphical.

4 · Adversarial reviews

Three independent models reviewed the same corpus with instructions to attack. Full texts preserved in the session; below are the load-bearing findings.

4.1 Claude (grounded in the repo)

Claude · most damningThe plan builds an inference tower on a capture foundation that varies from rich (Claude Code hooks) to blind (procwatch), and sequences the honesty layer — capture-quality metadata — behind the features that need it.
Claude · on WatchtowerWatchtower enforce mode contradicts the project's own prime directive ("never break the agent, fail silently") and is unenforceable on the codex adapter by architecture… It converts a passive observer with zero liability into a safety product with unbounded liability.
Claude · reframing insightThe roadmap is written for watching agents; the durable value is in not watching them… The product that wins is an interrupt system — the tool that stays silent for 47 minutes and then says exactly one true thing… The console framing optimizes for time-in-app; the correct metric is time saved out of app.
  • Sized the gap: ~5KLOC pipeline today vs. an order-of-magnitude larger proposal; 13 features ≈ a 3-year solo backlog against upstream formats that break quarterly — "the roadmap's true competitor is adapter rot."
  • Honest-TAM argument: single-agent interactive users already have a supervision UI (the agent's own); the real audience is multi-agent hands-off operators — thousands, not hundreds of thousands.
  • Noticed internal/index/attention.go already on the branch: "the codebase has already voted for the wedge; the ideation corpus hasn't noticed."
  • Cut list: Arena, Capsules, enforce-mode, menu-bar app, .afrec/reconstruction, causal edge taxonomy, custom query language.
  • Minimal roadmap: capture-quality honesty layer → attention & collision → threads-as-toggle (Claude Code sessions first) → plain filters + saved views → deterministic autopsy.

4.2 Antigravity / Gemini (outside-in, competitive)

agy · reframing insightAgent Firehose should not be an out-of-band observer retroactively trying to control agents — it should act as a local gateway sitting between the agent and the OS… This reframes the product from a "nice-to-have visual logger" into a must-have local firewall and cost-containment gateway.
agy · on the wedgeRetro-analysis observability is low-frequency… The real, immediate pain is uncontrolled token burn and loop death (an agent running npm test 40 times, one variable changed each time, $15 burned).
  • "Fallacy of the multi-agent orchestrator": local agent usage today is overwhelmingly serial — collision tooling solves a problem most developers don't have yet. (Adjudication in §5: partially accepted; collision ships as cheap feed events, not a dedicated surface.)
  • "Tailing catastrophe": adapters are hostage to upstream stdout/schema changes; a minor CLI release breaks parsers; without stable contracts, adapter maintenance overwhelms a small team.
  • Split-personality UI bottleneck (TUI vs. Tauri parity) — adopted as decision rule §3.5.
  • "Write-path illusion": out-of-band detection means rm -rf completes before a block prompt can render; true enforcement requires proxying the execution path. (This is the strongest single argument for cutting enforce-mode.)
  • Competitive: Langfuse/Phoenix/OTel already do trace graphs locally via Docker; agent-native UIs will always beat an outside observer on in-session fidelity; the differentiated lane is local-first agent-aware security/cost awareness.
  • Cut list: Arena, Repository Weather (menu-bar), Capsules. Proposed roadmap centers a stdio-wrapper protocol (af-run), loop/token firewall with SIGSTOP, secrets guardrails, a Tauri-only session viewer, git-native checkpoints.

4.3 Codex (engineering realism — deepest repo forensics)

Codex · most damningThe canonical history excludes a flagship supported agent. Codex can appear live while remaining absent from the spool, index, export, and future derivations. This invalidates Threads, Flight Recorder, Autopsy, Arena, and historical detectors before their algorithms are considered.
Codex · reframing insightThe product's real trust boundary is epistemic, not technical: Agent Firehose should be the system that tells users exactly what was observed, what was not observable, and which conclusions are justified by that evidence. Make unknown a first-class result.

Concrete code-level defects found (each verified against the current branch):

  • The spool is not canonical. Codex and procwatch events are broadcast-only — skipped at watcher start, streamed live, never spooled, never indexed (watcher.go:33, stream.go:68-82). "Two different truth models" pretending to be one product with varying capture quality.
  • Native correlation IDs are being thrown away. A real Codex fixture contains call_id, but the parser doesn't decode it, and exec_command call records are dropped in favor of completion records with no preserved ID (codex.go:170). Codex event IDs are re-randomized on every parse — not stable evidence anchors. Threads' prerequisite data is being discarded today.
  • attention.go already exhibits the source-dependent-falsehood problem: it treats every permission event as needs_input (but OpenCode maps both permission.updated and permission.replied there), recognizes only Claude-style completion names, and its 90-second idle heuristic marks any build longer than 90s as idle.
  • "Immutable raw events" contradicts the frozen privacy contract. The spool holds privacy-redacted events (balanced mode drops raw, truncates strings); future rules can't re-derive discarded information, and keeping an unredacted parallel log would violate frozen semantics. The foundation must say "immutable privacy-filtered observations." The balanced truncator is also shallow (nested maps pass through unchanged) — the artifact registry needs its own recursive privacy contract.
  • The index won't carry the proposed query load: index.Build reads the entire history into memory (ReadLastN(…, math.MaxInt)); /events has no cursor, time range, or server-side predicates; session queries scan whole day-files; SSE silently drops events past a 256-event buffer with no sequence numbers or gap markers — so capture-quality can't be a static badge; completeness changes mid-session.
  • Timestamps aren't one clock: Claude/OpenCode events get local capture time, Codex preserves source time; the spool preserves append order, not causal order — another reason inferred causal edges overreach.
  • Detector-by-detector capability audit: most "deterministic" detectors require state that isn't captured (no exit-status normalization for Claude Bash, no repo fingerprint, no content hashes, no normalized permission path for Codex). Each detector needs an adapter-capability predicate and an unknown result.

Codex's scope verdict: the plan is not 13 features — it's at least six hidden platforms (event-sourcing/derivation engine, query language + analytical index, filesystem recorder, inference framework, policy enforcement, portable formats/visualizations), each a permanent compatibility surface, proposed for a team already spanning Go, TS, Rust, multiple adapters, and two clients. Its minimal roadmap: Canonical Capture v2 (spool everything, preserve native IDs, gap markers, capability metadata) → Adapter Lab Lite → Durable Query Foundation → Flight Recorder Lite → Evidence Signals + Autopsy Lite. Notably it places Adapter Lab in the foundation, because fixture replay is how every later inference gets tested.

6 · Revised Phase 1 — "Make supervision calm" (~12–16 solo weeks)

Exit criterion: a user running two agents keeps the tool because it pings them correctly, the feed is skimmable in triage mode, and beautiful in ambient mode. No telemetry — validate via GitHub discussions.

0 · Capture integrity repair ~2–3 wk · from Codex's forensics

Precedes everything: (a) spool Codex and procwatch events — the contract says the spool is canonical, and today it isn't (broadcast-only paths in stream.go); (b) stop discarding native call_id in the codex adapter and preserve turn/tool IDs everywhere they exist (additive envelope fields); (c) stable event identity across reprocessing (no re-randomized IDs); (d) distinguish source time from capture time; (e) repo/worktree identity fields (prerequisite for honest collision detection); (f) fix the known attention.go semantic bugs (permission-replied ≠ needs-input; non-Claude completion names; 90s idle heuristic vs. long builds). All additive — no schema bump.

1 · Capture-quality honesty layer ~1–2 wk

Per-session fidelity fields (hook coverage rich/partial, transcript partial, responses-redacted…) on the index + /sessions; TUI session-header badge; a degrade-gracefully rule table every later derived feature must consult. Additive envelope fields only — no schema bump.

2 · Attention events + macOS surfaces ~2 wk

Three near-zero-FP derived events: needs-approval (blocked on permission), failed (session-level error), finished. Plus one agy-inspired class: runaway (same command failed N× with no intervening file change — the narrowest loop signature, coalesced per session). Delivery: macOS notification (osascript/terminal-notifier from the daemon), Tauri tray count, TUI attention strip. Finishes what attention.go starts. This is the retention feature.

3 · Feed craft pass (ambient mode) ~1–2 wk

Pause-on-scroll with accumulating counter; stable per-session color/glyph; gutter flow lines; the universal ≈ derived-row mark; color-discipline audit; latency budget enforcement at 100k events. This line item exists because the watchable firehose is a stated design goal — it's product work, budgeted.

4 · Turn grouping (Threads v0) ~2 wk

Opt-in toggle t. Native-ID grouping only; Claude Code sessions first (where tool_call correlation is real); collapse/expand extends the existing ×N coalescing; outcomes limited to active/ended; per-thread capture-fidelity inheritance.

5 · Hotkey lenses + filter + saved views ~1 wk

Keys 1–7: errors-only, current-repo, shell-only, files-only, active-sessions, warnings, all. / substring filter. Named views in a TOML file (composition without a grammar). Internal predicate engine structured enough for detectors to reuse later.

6 · Collision events ~1–2 wk

Two active sessions writing the same path within a window → one coalesced ≈ ⚠ collision feed event with evidence links. No radar surface. Doubles as the first proof of the derived-data store.

7 · Revised Phase 2 — "Make history explainable, honestly" (~9–12 solo weeks)

1 · Foundation: derived-data store + relationship fields + artifact registry ~2–3 wk

Additive envelope fields (tool_call_id, parent_event_id, thread_id); derivations in a separate NDJSON keyed to supporting event IDs with rule version + confidence + invalidation; artifacts addressable by hash (with an explicit recursive privacy + retention contract — Codex showed the balanced truncator doesn't recurse into nested payloads). Spool remains untouched canonical truth — reworded per Codex to "immutable privacy-filtered observations." Includes the durable query substrate: incremental disk-backed offsets so index.Build stops loading full history into memory, and cursors + time/session/source predicates on /events. Derived API under an explicitly-experimental /derived/* namespace. The adapter fixture CLI (item 6) starts here in parallel — fixture replay is how every derivation gets tested.

2 · Deterministic Session Autopsy ~2 wk

Markdown/JSON, leads with capture fidelity, sections: outcome (facts only) · actions · failures & retries · repo impact · permissions · unresolved. No summarizer plugin in v1. a from any session.

3 · Event-scoped replay ~2 wk

Step/scrub through a session's events with captured outputs and diffs, pager-style in the TUI; richer scrubber later in the desktop shell per §3.5. Explicit "repo state not reconstructed" framing. No .afrec.

4 · Why cards ~1–2 wk

w on any event → indented causal chain from native-ID edges only. No inferred edge types, no graph. If it can't build a high-confidence chain it says so ("no linked events captured").

5 · Session bundle export (Capsule v0) ~1 wk

/export → directory bundle: autopsy.md · events.ndjson · patches/ · manifest.sha256 · privacy-manifest.json. No continuation prompts, no adapter resume commands.

6 · Adapter fixture CLI ~1–2 wk, interleaved

firehose adapter dev --replay fixtures/ + coverage report. Justified inside Phase 2 as self-defense: adapter rot is the roadmap's true competitor, and Phase 2's derived features multiply the damage of silent capture drift.
