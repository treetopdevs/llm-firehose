# Release plan: 0.7.0

**Date:** 2026-11-23. **Base:** `origin/main` at 1735624, 0.6.0 plus 73 commits.
**Status:** proposed. Nothing here has been bumped, tagged or published.

The headline is the new Mac desktop shell, with the TUI moving by the same rules. The version
is a proposal: a minor bump fits a redesigned shell with one additive event field.

## What ships

- **Desktop:** the Mac shell (#89) and its review fixes (#90): source-list sidebar, light and
  dark, one kept time range, select then open, Back and Forward.
- **TUI:** `[` and `]` history, `n` for what needs you, `g` for all activity, Esc that clears a
  selection before climbing, selections held by key (branch `feat/tui-shell-feel`).
- **Capture:** `root_alias` places files captured through a symlinked path (#74), and Windows
  path-suffix matching is fixed (#92).
- **Site:** the marketing page (#91).

## Blocking gates

1. **See the shell in the real app.** No one has recorded a check of the new shell in WKWebView.
   #89 lists the overlay title bar as unverified: the traffic-light position and the 44px and
   80px insets are estimates, and drag regions are untested. #90 also had no WKWebView check.
   Run `pnpm -C apps/tauri-desktop tauri dev` and walk the checklist below. This needs the owner's
   eyes, because the look is the release.
2. **Land the TUI pass.** Review and merge `feat/tui-shell-feel`. Merges to `main` are
   human-approved.
3. **Accept the privacy note.** `root_alias` keeps a readable symlinked root in `balanced` history.
   It is a documented, approved exception within schema 1 (D134, `docs/contracts.md`). The
   release notes must say so plainly.

### Shell checklist (`tauri dev`, light and dark)

- [ ] Traffic lights sit cleanly with the sidebar open and collapsed.
- [ ] The window drags from the toolbar, and buttons in it do not start a drag.
- [ ] Double-clicking the toolbar maximises the window.
- [ ] Sidebar collapses under 900px, and the inspector overlays under 1100px.
- [ ] Project rows expand, Show all works, and rows align.
- [ ] Open a session, go Back: range, selection and scroll are all restored.
- [ ] Doctor badge count matches the warnings listed in Doctor.

## Steps

1. Merge the TUI pass, then confirm `main` is green.
2. On `release/0.7.0`, bump all of these:
   - `cmd/firehose/main.go`, `cmd/firehosed/main.go`
   - `apps/tauri-desktop/package.json`
   - `apps/tauri-desktop/src-tauri/tauri.conf.json`, `Cargo.toml`, `Cargo.lock`
3. Add a 0.7.x row to `docs/compatibility.md` covering `root_alias`: an older daemon does not
   record it, so files captured through a symlink stay under `Outside known worktrees`.
4. Rewrite the README's desktop section (lines 83-96 and 144-146). It still says Project is the
   landing view, Escape walks the altitudes and the attention strip stays visible.
5. Correct the runbook's precondition, which says "four places" but lists five files and omits
   `Cargo.lock`.
6. Draft the release notes by hand. goreleaser's generated changelog drops `docs:`, `chore:` and
   merge commits and has no place for the `root_alias` privacy note, so set the final notes on the
   GitHub Release after it is created.
7. Run the gates: `gofmt -l .`, `go vet ./...`, `go test ./...`,
   `pnpm -C apps/tauri-desktop test`, `pnpm -C apps/tauri-desktop build`, and `cargo test` in
   `src-tauri`.
8. Open the release PR. **The owner approves the merge and the `v0.7.0` tag push**, because the
   tag publishes to Homebrew. Approval for 0.6.0 does not carry over.
9. Confirm the publish: the GitHub Release has four CLI archives and both `.dmg`s, and the tap's
   formula and cask read 0.7.0. Then apply the release notes from step 6.
10. Only after that, update `site/index.html` in a follow-up PR: the `v0.6.0` link and version, the
    footer sample, and the "Three altitudes" section, which predates the worktree level and the new
    keys. `pages.yml` deploys on merge, so doing this earlier publishes a dead release link.
11. Upgrade this machine only when the owner chooses, because it restarts the real daemon on 4517:

   ```sh
   brew update
   brew upgrade treetopdevs/tap/firehose
   brew services restart firehose
   brew upgrade --cask treetopdevs/tap/agent-firehose
   ```

## Known risks

- **Flaky release test.** `TestEngineFeedReconcilesProjectedAttentionAfterOverflow` failed the
  first 0.6.0 release run and passed on rerun. It is unchanged and runs before goreleaser. If it
  is the only failure, rerun the failed job once. If it fails again, stop and investigate.
- **Load-sensitive desktop tests.** Wall-clock thresholds can fail under machine load. Rerun them
  and never relax a threshold.
- **Unsigned app.** The app is still unsigned, so the cask caveat about approving it once stays.
  Signing and the updater feed are out of scope for this release.
