## Relationship model

Exact source+session scope first. Events with missing captured IDs omitted and counted; duplicate event IDs collapsed deterministically with visible count (conflicting metadata counted and all records for conflicting IDs excluded from display and relationships). Stable time then ID ordering with invalid times explicitly marked, no semantic reliance on timestamps. Group by separate native namespaces call,turn,prompt,message,trace,request; never equate strings across namespaces. Group key JSON(kind,id); all groups are scoped to loaded exact source/session. Membership is association, not a causal arrow or proven start/end pair. No cross-session/cross-agent crawl or approximate matching.

Only directed reference: source=opencode, name=message.updated, message_id+parent_id. parent_id refers to parent message_id in this exact source/session per actual adapter fixtures. Label Native parent message reference. Tool/part message_id membership uses the message group, never assumes parent_id is captured event ID. Missing parent creates a visible zero-member message group/unavailable reference. Multiple distinct parents for one child and self-references are marked conflicting; no chosen parent. Native references may cycle; never recursively traverse or claim root cause. Generic parent_id and upstream_event_id are visible metadata only, counted as unsupported joins; never guessed. Message observations sharing one ID remain multiple receipts in one group. OpenCode terminal-only tool observations do not imply missing capture/start or current running state.

Model exports buildLoom(events,source,session) with events,groups,parents and omitted/duplicate/conflict/unsupported-reference counts; explicit stable shapes agreed among implementers. Derivation never mutates input.
